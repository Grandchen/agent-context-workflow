# Checkpoint contract

Use this reference at a meaningful milestone or user-requested checkpoint. First locate the existing canonical task record. Patch its minimum structure when authorized; create a new record only when no equivalent exists and the destination is authorized. The [optional template](../assets/checkpoint.md) is a checklist, not a replacement for an existing record. Keep one writer for task state.

The state record preserves:

- project/task identity, checkpoint revision, date, and canonical record pointer;
- all accepted outcomes, delivered work, remaining work, decisions, and open unknowns;
- source pointers and revisions, verification performed, limits, and changed inputs;
- exact unsaved work in an authorized artifact, or a plain statement that it is unavailable;
- external effects attempted, outcomes, unknown outcomes, and last intent/receipt evidence;
- next prerequisites and a safe action after resume.

Distinguish exact archived WIP from a summary or reconstruction. Read back the actual written record and verify its meaning. A checkpoint is evidence of state, never permission, a second source of truth, or a rollback of the outside world.
