# Agent Context Workflow：任务上下文工作流

给 AI 助手用的上下文管理 Skill：按需找资料、保留工作依据和进度，在换会话或中断后重建上下文、核对后继续。

和 AI 做一个项目，换会话或中断后，常常要重新解释目标、进度和限制。这个 Skill 把已有记录、资料和草稿重新组织起来，再核对现在的情况，帮助下一步接着做。

## 完整功能

| 功能 | 实际做什么 |
|---|---|
| 确定任务 | 先说清这次要做什么、要看哪些规则、能改什么，以及任务记录在哪里 |
| 找资料 | 先用已有索引和已知路径读相关原文与相互约束；找不到时再做范围有限的补找，并说明缺口 |
| 过滤与留存 | 先缩小冗长输出的读取范围；需要原样保留的内容放到获准位置，留下回查入口，不把摘要当原稿 |
| 区分状态 | 把事实、猜测、决定、精确工作稿和测试结果分开 |
| 保存检查点 | 在阶段节点把已完成、未完成、决定、来源版本和可恢复草稿写进已有记录，再读回确认 |
| 重建并核对 | 换会话或中断后按记录重建当前上下文，再核对任务、资料、权限和未知结果，再决定下一步 |
| 压缩与隔离 | 宿主明确提供且已授权才使用；否则手动保存、交接或先做只读检查 |

适合跨来源、跨轮次的研究、规划和小项目；一次性简单修改应保持轻量。

## 重建上下文，核对后继续

换会话或中断后，依据已保存的任务状态、来源和手头草稿，重建当前工作的上下文；再核对当前资料、权限和未知结果，决定下一步。

没有保存的精确内容就标为未知，不把后来重写的文字冒充原文。检查点是状态证据，不是新权限，也不是外部世界的回滚。

它沿用现有索引、计划和任务记录，按需展开相关参考；核心不要求数据库、后台服务、模型 API 或另一套 Skill。

当前版本为 `v0.1.0-preview`；原创项目文件采用 [MIT 许可证](LICENSE)，引用来源仍遵循各自许可。没有全局安装、后台服务、自动采集聊天或已验证的原生压缩适配器。通用流程不扩大模型窗口，也不保证无损恢复。

## 如何试用

让 Agent 显式读取 [SKILL.md](skills/context-workflow/SKILL.md)，说明任务和允许的动作。若安装到宿主技能目录，保留目录结构，并按该宿主实际说明核验发现结果。

- 开始：“对这个多步骤任务使用 context-workflow，复用已有索引与任务文件，轻量确定目标和验收。”
- 保存：“把当前阶段检查点保存到已有任务文件，保留未完成承诺、来源版本和未知结果；保存后读回核验。”
- 恢复：“先只读核对这个任务记录与当前原件，报告变化、未知副作用及可执行的下一步。”
- 仅规划：“提出检查点草案，不写文件。”

没有文件工具时只返回可复制草案，不声称已经保存；没有原生压缩工具时采用手动交接，不猜测 token 百分比。检查点不能替代权限，旧命令不自动重放。同范围仍有效的批准可以沿用，过期、已消费或扩大范围的动作需另行判断。

## 结构与验证

一个精简入口按需读取导航、检查点、恢复或压缩参考；任务状态留在使用者自己的项目。研究来源库不在每次执行时预加载。

参见 [合成示例](examples/README.md)、[能力矩阵](COMPATIBILITY.md)、[来源与复用记录](SOURCES.md) 和 [验证状态](STATUS.md)。`python evals/check_package.py` 只检查包结构、链接和公开资料边界，不代表模型行为、实际会话压缩或性能收益已通过。

本轮文件往返与独立上下文恢复的材料见 [连续性试验](evals/continuity-trial/README.md)。首次写入的措辞问题与修正历史保留，不把一次合成场景当作所有宿主通过。
